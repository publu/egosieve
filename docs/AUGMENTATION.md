# Observable-issue augmentation

`egosieve-build-corpus` builds a reproducible positive-only corpus from videos
you are authorized to use and annotations in `egosieve.training/v1`.
It creates transformed MP4 clips, parseable training records, per-clip
provenance, explicit skip records, and a build manifest.

The builder does not decide whether a license permits training or creating
derivatives. You must pass every accepted license identifier explicitly. The
match is exact, and each generated record retains the source record's license,
`group_id`, and preassigned `split`.

## Input

Media paths are resolved against `--media-root`, or against the annotation
file's directory when no media root is supplied. Relative paths may not escape
that root. A minimal source record looks like this:

```json
{
  "schema": "egosieve.training/v1",
  "id": "episode-001",
  "group_id": "session-019",
  "video": "videos/episode-001.mp4",
  "license": "CC-BY-4.0",
  "split": "train",
  "attribution": "Example Dataset contributors",
  "windows": [
    {
      "start_s": 8.0,
      "end_s": 14.0,
      "annotator": "human:reviewer-12",
      "label_provenance": {
        "readiness": {"kind": "human"},
        "issues": {"kind": "human"},
        "boundaries": {"kind": "unlabeled"}
      },
      "review_count": 2,
      "rubric_version": "egosieve-annotation/v1",
      "hand_regions": [[0.18, 0.42, 0.25, 0.31]]
    }
  ]
}
```

`hand_regions` is optional for all transformations except
`hand_occlusion`. It is a non-empty list of `[x, y, width, height]` boxes in
normalized coded-frame coordinates whose union covers the acting hand's
locations throughout the window. If it is absent, that transformation is
recorded in `skipped.jsonl`; the builder does not invent a hand location or a
positive label.

Every member of one `group_id` must have the same source `split`. The builder
rejects a corpus that would carry a group across split boundaries.

## Build

```bash
egosieve-build-corpus annotations.jsonl derived-corpus \
  --media-root /data/authorized-videos \
  --allowed-license CC-BY-4.0
```

Repeat `--allowed-license` for every exact declared identifier you reviewed.
Use repeated `--transform` options to select a subset; all supported
transformations are generated by default.

The equivalent Python API is:

```python
from egosieve.training import AugmentationConfig, build_augmented_corpus

result = build_augmented_corpus(
    "annotations.jsonl",
    "derived-corpus",
    media_root="/data/authorized-videos",
    allowed_licenses=["CC-BY-4.0"],
    config=AugmentationConfig(
        transforms=("blur", "freeze", "scene_cut"),
        output_fps=12,
    ),
)
print(result.manifest_path)
```

| Transformation | Positive issue target | Programmatic evidence |
| --- | --- | --- |
| `blur` | `blur` | Strong Gaussian blur |
| `exposure` | `exposure` | Strong underexposure and contrast reduction |
| `camera_instability` | `camera_instability` | Time-varying translated crop |
| `freeze` | `duplicate_frames` | A fixed frame replaces a contiguous interval |
| `scene_cut` | `scene_cut` | A hard temporal splice removes a middle interval from the same source window |
| `hand_occlusion` | `hand_occlusion` | An opaque overlay covers the union of declared hand boxes |
| `no_hands` | `no_hands` | Faithful re-encode, only when the source window already has a valid positive `no_hands` label |
| `low_hand_activity` | `low_hand_activity` | Faithful re-encode, only when the source window already has a valid positive `low_hand_activity` label |

The first six rows are controlled proxies for observable failure modes, not
substitutes for naturally occurring examples. In particular, translated crops
do not cover every form of camera instability, and a same-source temporal
splice is only one kind of edit discontinuity. `no_hands` and
`low_hand_activity` are never manufactured: an ineligible source window is
written to `skipped.jsonl` with `source_positive_required`. Even a valid
positive is skipped with `human_issue_provenance_required` unless
`label_provenance.issues.kind` explicitly says `human` or `human-derived`.
Train or pretrain with programmatic examples, then calibrate and evaluate on
independently human-reviewed real video.

## Positive-only target policy

Each generated window has exactly one known-positive issue target. Its
`issue_valid` bit is true; every other issue is omitted and therefore unknown.
Interaction boundaries are invalid. Readiness is invalid for every
corruption-derived window. A faithful human-inherited re-encode also retains
readiness only when the source explicitly supplied a valid target. Corruption
windows use:

```json
{
  "annotator": "controlled-corruption:egosieve.augmentation/v1",
  "label_provenance": {
    "readiness": {"kind": "unlabeled"},
    "issues": {
      "kind": "programmatic-controlled-corruption",
      "positive_only": true
    },
    "boundaries": {"kind": "unlabeled"}
  }
}
```

Faithful `no_hands` and `low_hand_activity` outputs use
`label_provenance.issues.kind: human-derived`, while recording whether their
source issue evidence was `human` or `human-derived`. They are not generated
from legacy, unlabeled, or programmatic issue provenance. A source readiness
target is inherited as `human-derived` only when it is valid, has explicit
human-grounded readiness provenance, and carries `review_count >= 2` plus a
non-empty `rubric_version`. Boundaries remain unlabeled.

Exact valid source `review_count` and `rubric_version` fields are promoted only
for those faithful human-derived rows so grouped held-out evidence can survive
corpus compilation. These fields may be declared on the source window or at
the top level of its `label_provenance`. For every controlled corruption they
appear only under `label_provenance.source_review` and cannot make the proxy
look human-reviewed.

An untouched or unmentioned issue is never labeled negative. Provenance is
task-specific and is never inferred from an annotator-name prefix.

## Output and reproducibility

The destination must not already exist. Files are first written to a sibling
directory ending in `.building`, verified, and atomically renamed after the
manifest is complete.

```text
derived-corpus/
  annotations.jsonl
  provenance.jsonl
  skipped.jsonl
  manifest.json
  media/
    blur/*.mp4
    exposure/*.mp4
    camera_instability/*.mp4
    freeze/*.mp4
    scene_cut/*.mp4
    hand_occlusion/*.mp4
    no_hands/*.mp4
    low_hand_activity/*.mp4
```

`provenance.jsonl` records the source record and window identity, source and
output SHA-256 values, transformation parameters and filter graph, exact
argument-vector command, shell-free execution flag, and probe commands.
`manifest.json` records the complete ffmpeg and ffprobe version output,
resolved executable and binary hashes, the original source-annotation path and
hash separately from the generated annotation artifact, configuration,
license/split policies, artifact hashes, and generated/skip counts.

Derived identifiers and MP4 bytes are deterministic for the same source
bytes, annotations, configuration, and toolchain. The toolchain identity is
part of each derived identifier. Absolute build paths in command provenance
truthfully describe the particular run and may differ when the destination
changes.

Before publishing a corpus, retain the upstream license text, attribution,
and source revision alongside this generated manifest. Review faces, screens,
documents, bystanders, consent, and redistribution rights separately; a
successful build is not a privacy or legal clearance. Provenance deliberately
contains exact absolute command paths, so review it for workstation or account
names before publishing it; if redaction is required, publish a separately
identified redacted view and retain the original build record privately.
